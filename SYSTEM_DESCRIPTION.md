|---------|-----------|

| **Многоязычность** | Обработка описаний оборудования на английском, русском и китайском языках |

## Компоненты и модули

### Основные модули приложения

#### `app_hybrid.py` — Flask приложение

**Роль:** Маршрутизация HTTP запросов, управление сеансами, координация между фронтенд и бизнес-логикой

**Ключевые маршруты:**

```python
GET  /                    # Главная страница
GET  /login              # Форма входа
POST /login              # Обработка входа
GET  /logout             # Выход
GET  /dashboard          # Панель оборудования
GET  /audit              # Форма аудита
POST /api/audit          # Отправка текста для анализа
GET  /audit-result       # Результаты аудита
GET  /upload-pdf         # Загрузка PDF
POST /api/equipment      # Получение списка оборудования
GET  /suppliers          # Страница поставщиков
GET  /products           # Страница продуктов
GET  /supply-chain       # Страница цепочки поставок
GET  /status             # Статус системы
GET  /api/status         # JSON статус
```

**Режим работы:**

```python
DATABASE_URL = os.environ.get('DATABASE_URL')
IS_PRODUCTION_MODE = (DATABASE_URL is None or DATABASE_URL == "")

if IS_PRODUCTION_MODE:
    # Использование JSON файла (demo_data.json)
    equipment = json_manager.get_all()
else:
    # Использование PostgreSQL через SQLAlchemy
    equipment = IndustrialEquipment.query.all()
```

#### `analytics.py` — Ядро обработки данных

**Роль:** Извлечение структурированных параметров из текста, подготовка признаков, предсказание отказов оборудования

**Основные функции:**

1. **`get_structured_data_via_llm(text_segment: str)`** — LLM обработка
   - Отправляет текст в Groq API
   - Настраивает систему на детерминированный режим (temperature=0.1)
   - Запрашивает JSON ответ со структурированными параметрами
   - Возвращает словарь: `{equipment_type, model, supplier, parameters}`
   - При ошибке возвращает `None` и переходит к резервному методу (regex)

2. **`class SmartParser`** — Извлечение параметров

   - `extract_all_numbers(text)` — поиск всех числовых значений и их контекста
   - `detect_equipment_type_semantic(text)` — определение типа оборудования через BERT эмбеддинги
   - `prepare_features(equipment_type, parameters)` — нормализация признаков для ML моделей

3. **`class MLInferenceEngine`** — Машинное обучение

   - Загрузка предварительно обученных моделей (.pkl файлы)
   - Нормализация входных признаков с использованием `scaler.pkl`
   - Вычисление вероятности отказа через `model.predict_proba()`
   - Определение уровня риска на основе вероятности

4. **`intelligent_audit(text, db_session, use_bert=True)`** — Главная функция аудита

   **Шаги обработки:**
   
   - ШАГ 1: LLM извлечение через Groq
   - ШАГ 2: Поиск всех числовых параметров (regex)
   - ШАГ 3: ML предсказание вероятности отказа
   - ШАГ 4: BERT детектирование типа оборудования
   - ШАГ 5: Поиск эталонных данных из БД
   - Возвращает полный отчёт: `{equipment_type, parameters, ml_prediction, benchmark}`

5. **`class DatabaseBenchmark`** — Сравнение с эталонными данными
   - Запросы к БД для получения средней/минимальной/максимальной цены
   - В режиме JSON использует встроенные данные из demo_data.json

#### `pdf_parser.py` и `debug_parser.py` — Обработка PDF

**Роль:** Извлечение текста из PDF документов и парсинг структурированной информации

- `pdf_parser.py` — основной модуль для работы с PDF (pdfplumber)
- `debug_parser.py` — вспомогательные функции и эвристики для отладки

#### `main.py` — Автономный конвейер

**Роль:** Оркестрация процесса автоматического поиска поставщиков и прогнозирования спроса

**Основной рабочий процесс:**

1. Поиск поставщиков по ключевому слову в интернете
2. Сканирование веб-страниц поставщиков
3. Очистка и структурирование извлечённых таблиц
4. Симуляция данных цепочки поставок
5. Обучение и оценка ML моделей прогнозирования спроса
6. Экспорт результатов в CSV и графики

## Жизненный цикл запроса

### Пример: аудит оборудования

```
1. ФРОНТЕНД (браузер)
   └─ Пользователь заполняет форму в audit.html
   └─ Нажимает кнопку "Запустить аудит"
   └─ JavaScript отправляет POST запрос: /api/audit
      {text: "Насос KS-500 с 1800 об/мин и давлением 150 бар"}

2. FLASK МАРШРУТ (app_hybrid.py)
   └─ @login_required проверяет сеанс
   └─ Извлекает текст из JSON тела запроса
   └─ Вызывает intelligent_audit(text, db_session)

3. БИЗНЕС-ЛОГИКА (analytics.py)
   │
   ├─ ШАГ 1: LLM обработка
   │  └─ get_structured_data_via_llm(text)
   │  └─ Groq API: "Какой тип оборудования?"
   │  └─ Результат: {equipment_type: "pump", model: "KS-500", parameters: {rpm: 1800, pressure: 150}}
   │
   ├─ ШАГ 2: Регулярные выражения
   │  └─ SmartParser.extract_all_numbers(text)
   │  └─ Результат: {all_values: [500, 1800, 150], contexts: ["RPM", "pressure"]}
   │
   ├─ ШАГ 3: ML предсказание
   │  └─ MLInferenceEngine.prepare_features("pump", parameters)
   │  └─ Загружает models/pump.pkl
   │  └─ model.predict_proba() → вероятность отказа: 0.23
   │  └─ Результат: {failure_probability: 0.23, risk_level: "low"}
   │
   ├─ ШАГ 4: BERT детектирование
   │  └─ SmartParser.detect_equipment_type_semantic(text)
   │  └─ Эмбеддинг текста через sentence-transformers
   │  └─ Сравнение с эмбеддингами типов оборудования
   │
   └─ ШАГ 5: Эталонные данные
      └─ DatabaseBenchmark.get_price_stats(db_session, "pump")
      └─ SELECT AVG(price) FROM industrial_equipment WHERE category="pump"
      └─ Результат: {average_price: 4500, sample_count: 12}

4. JSON ОТВЕТ (Flask)
   └─ Возвращает:
   {
     "success": true,
     "audit": {
       "equipment_type": "pump",
       "model": "KS-500",
       "parameters": {rpm: 1800, pressure: 150},
       "ml_prediction": {
         "failure_probability": 0.23,
         "risk_level": "low"
       },
       "database_benchmark": {
         "average_price": 4500,
         "sample_count": 12
       }
     }
   }

5. ФРОНТЕНД (JavaScript)
   └─ Парсит JSON ответ
   └─ Обновляет DOM с результатами
   └─ Отображает: "Тип: Насос | Риск: Низкий | Средняя цена: $4500"
```

### Время обработки

| Этап | Компонент | Время | Примечания |
|------|-----------|-------|-----------|
| Фронтенд | HTML форма + JS | <100ms | Без сервера |
| Flask маршрут | URL mapping + проверка | ~5ms | Кэш попадание |
| LLM вызов | Groq API | 1-3s | Зависит от сети |
| BERT эмбеддинг | sentence-transformers | ~200ms | GPU ускорение если доступно |
| ML вывод | model.predict_proba() | ~50ms | CPU вывод |
| Запрос БД | PostgreSQL AVG() | ~10ms | Индексированный запрос |
| JSON сериализация | Flask | ~10ms | Маленький payload |
| **Итого** | **Конец-в-конец** | **1.3-3.5s** | Доминирует Groq API |

## Функциональные страницы

### Страница аудита (`/audit`)

**Описание:** Форма для ввода текстового описания оборудования или загрузки PDF файла

**Входные данные:**
- Свободный текст на английском, русском или китайском
- PDF документы (техническая документация, спецификации)

**Обработка:**
1. Текст (или извлечённый из PDF) отправляется в LLM через Groq
2. LLM преобразует текст в структурированный JSON с параметрами
3. Параметры нормализуются и передаются в ML модели
4. Вычисляется вероятность отказа и уровень риска

**Выходные данные:**
- Тип оборудования
- Модель и производитель
- Извлечённые параметры (обороты, давление, температура и т.д.)
- Прогноз вероятности отказа
- Сравнение с эталонными ценами

### Страница поставщиков (`/suppliers`)

**Описание:** Каталог поставщиков оборудования, извлечённых из интернета и синтезированных данных

**Источники данных:**
- Данные из `companies_china_50.csv` — реальный список китайских производителей
- Часть данных симулируется из-за ограничений NDA и сканирования

**Отображаемая информация:**
- Название компании
- Страна и город
- Веб-сайт
- Количество продуктов
- История продаж и выручка

### Страница продуктов (`/products`)

**Описание:** Каталог продуктов поставщиков

**Содержит:**
- ID продукта
- Название и описание
- Производитель (связь с поставщиком)
- Техническими спецификациями
- Ценовой диапазон

### Страница цепочки поставок (`/supply-chain`)

**Описание:** Визуализация взаимодействия между поставщиками, продуктами и продажами

**Элементы:**
- Граф зависимостей поставщик → продукт → заказ
- История продаж с временными рядами
- Объёмы и выручка

## Обработка данных в аудите

### Компонент LLM (Groq)

**Функция:** `get_structured_data_via_llm(text_segment: str)`

**Как работает:**

1. **Построение промта:**
   ```
   Act as a Senior Industrial Systems Engineer. 
   Parse technical data into strict JSON format.
   
   TEXT TO ANALYZE: [user text up to 4000 characters]
   ```

2. **Вызов Groq API:**
   - Модель: `llama-3.3-70b-versatile`
   - Temperature: 0.1 (низкая вариативность, детерминированные ответы)
   - response_format: json_object (принудительный JSON вывод)

3. **Пример обработки:**
   ```
   INPUT:  "Pump KS-500 with 1800 rpm and 150 bar pressure"
   OUTPUT: {
     "equipment_type": "pump",
     "model": "KS-500",
     "supplier": null,
     "parameters": {
       "rpm": 1800,
       "pressure": 150
     }
   }
   ```

4. **Обработка ошибок:**
   - Если GROQ_API_KEY не установлен → функция возвращает None
   - Таймаут API → переход на резервный метод (regex парсинг)
   - Ошибка парсинга JSON → возвращает None
   - Результат: аудит продолжается с использованием SmartParser

### Компонент парсера (SmartParser)

**Резервный механизм** при недоступности LLM

**Методы:**
- Регулярные выражения для поиска чисел, единиц измерения
- Словари ключевых слов для типов оборудования
- Многоязычная поддержка (EN, RU, CN)

### Компонент ML моделей

**Входные признаки:**
- Нормализованные параметры (обороты, давление, температура и т.д.)
- Разные признаки для разных типов оборудования

**Выходные значения:**
- Вероятность отказа (0.0-1.0)
- Уровень риска (low, medium, high) на основе вероятности

**Модели:**
- `pump.pkl` — для насосов
- `valve.pkl` — для клапанов
- `cooler.pkl` — для охладителей
- `accumulator.pkl` — для накопителей

## Гибридный режим работы

### JSON режим (демо)

**Активируется при:**
- `DATABASE_URL` не установлена (или пуста)
- `IS_PRODUCTION_MODE = true`

**Источник данных:**
- Файл `demo_data.json` (встроенный в приложение)
- Содержит 234 примера оборудования разных типов

**Преимущества:**
- Нет зависимостей от БД
- Работает в облаке без подключений к БД
- Полностью автономный режим
- Быстрый запуск

**Ограничения:**
- Данные только для чтения
- Нет сохранения новых записей
- Фиксированный размер данных

### PostgreSQL режим (разработка)

**Активируется при:**
- `DATABASE_URL` установлена (например: `postgresql://user:pass@localhost:5432/db_name`)
- `IS_PRODUCTION_MODE = false`

**Источник данных:**
- Таблица `industrial_equipment` в PostgreSQL
- Динамическое изменение количества записей
- Сохранение новых аудитов

**Возможности:**
- Полный CRUD (Create, Read, Update, Delete)
- Аналитические запросы
- Массовый импорт данных

**Подключение:**
```python
from sqlalchemy import create_engine
engine = create_engine(DATABASE_URL)
session = Session(bind=engine)
equipment = session.query(IndustrialEquipment).all()
```

### Логика выбора режима

```python
# app_hybrid.py, строка 47
DATABASE_URL = os.environ.get('DATABASE_URL')
IS_PRODUCTION_MODE = (DATABASE_URL is None or DATABASE_URL == "")

if IS_PRODUCTION_MODE:
    # JSON режим
    equipment = json_manager.get_all()
    avg_price = benchmark.get_from_json()
else:
    # PostgreSQL режим
    equipment = IndustrialEquipment.query.all()
    avg_price = db.session.query(func.avg(IndustrialEquipment.price))
```

## Интеграция с Docker

### Docker Compose стек

**Файл:** `infrastructure/docker-compose.yml`

**Сервисы:**
- **postgres** — базу данных (PostgreSQL 15)
- **redis** — кэширование сеансов
- **kafka** — очередь сообщений
- **spark** — распределённая обработка данных
- **prometheus** — сбор метрик

**Запуск:**
```bash
docker-compose -f infrastructure/docker-compose.yml up -d
```

### Docker образ приложения

**Файл:** `Dockerfile`

**Процесс сборки:**
1. Базовый образ Python 3.9
2. Установка зависимостей из requirements.txt
3. Копирование кода приложения
4. Установка переменных окружения
5. Запуск Flask на порту 5000

**Сетевое взаимодействие:**
- Внутри Docker сети: Flask обращается к PostgreSQL как `postgres:5432`
- Имя сервиса в docker-compose.yml используется как hostname

## Резюме

Система реализует многоуровневую архитектуру для анализа оборудования и управления цепочкой поставок:

- **Фронтенд:** Интерактивный веб-интерфейс на Flask/Jinja2
- **Бизнес-логика:** LLM обработка (Groq), ML предсказания (scikit-learn), парсинг текста
- **Хранилище:** Гибридная поддержка JSON (демо) и PostgreSQL (production)
- **Внешние сервисы:** Groq для LLM, sentence-transformers для BERT, BeautifulSoup для сканирования
- **Масштабируемость:** Docker Compose для интеграции Spark, Kafka, Prometheus

Система обработает текстовые описания оборудования, извлекает структурированные параметры через LLM, прогнозирует вероятность отказа через ML модели и предоставляет сравнение с эталонными данными из БД.
